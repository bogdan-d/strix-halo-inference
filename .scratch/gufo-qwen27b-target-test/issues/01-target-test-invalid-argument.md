# 01: Gufo's qwen27b_target_test fails with "invalid argument" on this host

Status: resolved

Found on November 23 during the 27B LoRA side-path work (ticket [10](../../abliterated-trials/issues/10-gufo-27b-q4-adapter-routes.md)). The fork's real-weight GPU test `qwen27b_target_test` ends with `invalid argument` on UD-Q4_K_XL, for stock weights as well as with an adapter, so the LoRA work did not cause it.

## Known

- Reproduced twice on unmodified upstream main `e228a4c7fb751ba01f5fb22d11b1758a0856e392`, with stock `unsloth/Qwen3.8-27B-GGUF/Qwen3.8-27B-UD-Q4_K_XL.gguf`, on Radeon 8060S (gfx1151), using the Podman/Nix GPU test build with ROCm CLR 10.1. The default target test exits 1. Original fork logs are `sp-target-stock.log` and `sp-target-lora.log`. All log names below are relative to `/var/mnt/xdata/code/strix-halo/gufo-build/logs/`.
- At the first 24-token prefix of the 128-token executor, `tests/models/qwen27b/target_test.cpp:581` calls `SaveSnapshot`. The first FP16 K-plane copy at `src/models/qwen/hip/arena.cpp:584` reaches `hipMemcpy2DAsync` at `src/core/hip/snapshot_transfer.hpp:52`. The API immediately returns `hipErrorInvalidValue` with dst pitch 49,152 B, src pitch 262,144 B, width 49,152 B, height 16, kind device-to-device, on the snapshot transfer stream. The producer stream synchronized successfully. See `target-upstream-default.log` and `target-upstream-hip.log.gz`.
- The arena reserves a contiguous virtual KV range and backs it with independent 2 MiB HIP mappings. The trace shows all four mappings of the 8 MiB arena with read/write access. The first eight strided K rows fit inside the first mapping. Row nine starts in the second. A model-free probe reproduced the same error in both capture and restore with 16 rows. Eight rows passed, as did 16 rows with one `hipMalloc` allocation or with the shorter pitches for 32- and 64-token capacities. See `target-upstream-probe.log`.
- The upstream `--prefill-only` path also fails after a successful 64-token prefill at capacity 12,288 (src pitch 25,165,824 B, dst pitch and width 131,072 B, height 16). See `target-upstream-prefill.log.gz`. The fork release CLI reproduces at capacity 4,096 with `gufo bench -p 1 -n 1 -r 1 -d 24` (src pitch 8,388,608 B). Its benchmark driver calls the same upstream snapshot code at `src/models/qwen/drivers.cpp:555`. The same release CLI completed both prefill and decode at depth zero, which skips the prefix snapshot. See `target-fork-bench-depth24.log.gz` and `target-fork-bench-depth0.log`.
- This affects the executor snapshot API and nonzero-depth benchmarks. The ordinary FP16 Qwen serving cache transfers one layer/plane at a time in `ContinuationAdapter::TransferRows` (`src/models/qwen/continuation_adapter.cpp:866`), through a different path. No serving failure was established. Only gfx1151 and the pinned ROCm runtime were exercised.
- A diagnostic copy override issued 1D device copies per row, split at 2 MiB boundaries on the same stream. The upstream fingerprint mode completed all 27 logit fingerprints, the fork depth-24 benchmark completed prefill and decode, and a synthetic save/restore round trip crossing a mapping boundary was byte-exact. See `target-upstream-fingerprints-control.log`, `target-fork-bench-control.log`, and `target-upstream-probe.log`. The override is a diagnostic control. The local fix and its measurements are recorded below.
- Fixed locally on Gufo branch `fix/qwen-snapshot-mapped-kv`, commit `41a64e6a1521c368568a73e9a43589635dc39de0` on `e228a4c7`. Device snapshot capture and restore, compact restore, and the FP32 continuation adapter bound each pitched copy by both operands’ 2 MiB page edges and their respective pitches. A straddling row uses bounded 1D copies. Both restore paths drain the arena stream before propagating a submission error. The FP16 serving adapter keeps its contiguous transfer path.
- The original snapshot fixture failed against upstream and passed for GPU and serialized restores on the candidate. The additional five-row mapped-to-mapped round trip at unequal pitches failed on the one-sided copy implementation from `481f806f` (`hipErrorInvalidValue`) and passed byte-exactly on the amendment, including the destination padding after copying back. See `review-negative-kv2.log` and `review-kv.log`.
- The stock default and prefill-only target checks passed. All 27 fingerprints matched the upstream diagnostic control. The depth-24 benchmark completed both rows (8.71 pp1 and 12.04 tg1 tokens/s). The adapter’s seven text checks passed, including FP32 at 8,203 tokens. The default run exited 1 because it requires an adjacent projector. A follow-up `--image-only` run with temporary adjacent links to the target and `vision/mmproj-BF16.gguf` passed both image checks. See `review-{default,prefill,fingerprints,bench,adapter,adapter-image}.log`.
- At 4,096 and 32,768 tokens, the upstream mapped arena fails on its first save. The amended candidate’s median save + restore times were 15.533 and 79.160 ms over five samples after warmup, compared with 15.375 and 76.347 ms for the previous one-sided fix. See `review-mapped-{4096,32768}.log`.
- The upstream `long-context` and `cache` text suites passed in both AR and DFlash2 on Q4 (11 report groups and 50 requests per mode, including disk restart). The image-enabled runs also passed in both modes (15/15 groups and 70 requests each). AR executed zero draft tokens in both configurations. DFlash2 accepted 303/512 proposed tokens in the text run and 474/830 in the image-enabled run. See `review-functional-{fix,vision-fix}-{off,dflash2}/report.json`. The flake check passed with 200 CTest passes, 10 skips, and a successful lock-mode build. Format, extension API, isolation, docs and generated infrastructure checks passed. See `review-{flake,ci}.log` and the PR draft.
